## 프로젝트 개요

### 목적

노션에서 작성한 견적서를 클라이언트에게 전문적인 웹 인터페이스로 제공하고, PDF 저장 기능을 통해 공유 및 관리의 편의성을 높입니다.

### 핵심 가치 제안

- 🔗 **간단한 공유**: 클라이언트는 노션 계정 없이 링크 클릭만으로 견적서 확인
- 📱 **반응형 디자인**: 모든 디바이스(PC, 태블릿, 모바일)에서 최적화된 뷰
- 📥 **PDF 저장**: 전문적인 형식의 PDF 자동 생성 및 다운로드
- 🔐 **간단한 관리**: 패스워드 기반 관리자 대시보드로 모든 견적서 목록 조회
- 🎨 **브랜드 일관성**: 회사 로고와 브랜딩 요소 자동 적용

### 해결하는 문제

| 문제                        | 기존 방식          | 솔루션                     |
| --------------------------- | ------------------ | -------------------------- |
| 클라이언트가 노션 계정 필요 | 노션 공유 링크     | 웹 기반 뷰어 (계정 불필요) |
| PDF 변환 번거로움           | 수동 PDF 저장      | "PDF 저장" 버튼 (1클릭)    |
| 디자인 일관성 부족          | 노션 기본 템플릿   | 통일된 웹 디자인           |
| 관리자 편의성 낮음          | 노션에서 직접 조회 | 관리자 대시보드            |

## 사용자 여정 플로우

### 사용자 타입

1. **클라이언트**: 견적서를 받아 확인하는 최종 사용자
2. **관리자**: 견적서를 생성/관리하고 클라이언트에게 공유하는 담당자

### 전체 사용자 여정

```
[클라이언트]
관리자로부터 견적서 링크 수신
         ↓
공개 링크 접근 (비밀번호 불필요)
         ↓
견적서 조회 (웹 뷰어)
         ↓
├─ PDF 다운로드 또는
├─ 인쇄 또는
└─ 링크 공유


[관리자]
노션에서 견적서 작성
         ↓
관리자 대시보드 접속 (패스워드)
         ↓
전체 견적서 목록 조회
         ↓
특정 견적서 선택
         ↓
├─ 클라이언트 공개 링크 복사
├─ 견적서 미리보기 또는
└─ 링크 QR 코드 생성 (향후)
```

### 클라이언트 상세 여정

```
수신: "https://invoice.example.com/view/INV-2026-001"
   ↓
접근 → 견적서 상세 페이지 로드
   ↓
정보 확인:
  • 발행사 정보 (로고, 회사명)
  • 클라이언트 정보
  • 항목별 내역
  • 소계 / 세금 / 합계
  • 발행일, 유효기간
   ↓
액션 선택:
  ├─ [PDF 저장] → 다운로드 (파일명: 견적서_INV-2026-001_클라이언트명.pdf)
  ├─ [인쇄]    → 브라우저 인쇄 대화상자
  └─ [종료]    → 페이지 이동
```

### 관리자 상세 여정

```
접근: "https://invoice.example.com/dashboard"
   ↓
패스워드 입력 및 인증
   ↓
대시보드 로드:
  • 견적서 목록 (검색, 필터 기능)
  • 각 견적서별 상태 표시
   ↓
견적서 선택
   ↓
상세 정보 확인 및 액션:
  ├─ [공개 링크 복사] → 클립보드 복사
  ├─ [미리보기]       → 웹 뷰어로 미리 확인
  ├─ [삭제] (향후)    → 견적서 목록에서 제거
  └─ [뒤로가기]       → 목록으로 돌아가기
```

## 핵심 기능 명세

### F-01: 견적서 조회 (공개 웹 뷰어)

**기능 ID**: `F-01`
**영문명**: Invoice Public Viewer
**범위**: MVP (필수)
**권한**: 모든 사용자 (비인증)

**설명**:

- 공개 링크를 통해 특정 견적서의 상세 정보를 웹에서 조회
- 노션 API를 통해 실시간 데이터 수집 및 렌더링
- 반응형 레이아웃으로 모든 디바이스 지원

**주요 기능**:

- 견적서 데이터 표시 (발행사 정보, 클라이언트명, 항목 리스트)
- 자동 계산 (소계, 세금 10%, 합계)
- 회사 로고 및 브랜드 컬러 적용
- 인쇄 최적화 CSS

**입력**:

- URL 파라미터: `slug` (견적서 고유 ID)

**출력**:

- 렌더링된 견적서 페이지
- 메타데이터 (OG 태그로 공유 시 미리보기 제공)

**입력**:

- 현재 렌더링된 견적서 DOM

**출력**:

- PDF 파일 (브라우저 다운로드)

  │   │
  │   └─ /api/invoices             [F-06] 노션 API 동기화 (백엔드)

  └─ 정적 페이지

## 페이지별 상세 기능

### 페이지 1: 견적서 공개 뷰어 (`/view/[slug]`)

**페이지 ID**: `P-01`
**기능**: F-01, F-02
**권한**: 모든 사용자 (비인증)
**이전 페이지**: 없음 (외부 링크에서 진입)
**다음 페이지**: 없음 (PDF 다운로드 또는 인쇄)

#### 역할

- 공개 링크를 통해 누구나 견적서를 조회할 수 있는 페이지
- 견적서 데이터를 전문적으로 렌더링하고 PDF 생성 기능 제공

#### 진입 경로

1. **클라이언트**: 관리자로부터 받은 공개 링크 클릭
   - `https://invoice.example.com/view/INV-2026-001`
2. **관리자**: 대시보드에서 "미리보기" 클릭

#### 주요 구성 요소

##### 1. 헤더 영역

- **회사 로고**: 왼쪽 상단 (선택사항, 노션 데이터 기반)
- **페이지 제목**: "견적서"
- **액션 버튼**:
  - [PDF 저장] - 다운로드 (우측 상단)
  - [인쇄] - 인쇄 대화상자 (우측 상단)
  - [공유] - 링크 공유 (우측 상단, 향후)

##### 2. 발행사 정보 영역

- 회사 로고 (노션 이미지 참조)
- 회사명, 주소, 연락처, 이메일
- 사업자등록번호

##### 3. 견적서 정보 영역

- **견적서 번호**: 예) INV-2026-001
- **견적 제목**: 예) 웹사이트 구축 프로젝트
- **발행일**: YYYY-MM-DD 포맷
- **유효기간**: YYYY-MM-DD ~ YYYY-MM-DD

##### 4. 클라이언트 정보 영역

- **회사명**
- **담당자명**
- **주소**
- **연락처**
- **이메일**

##### 5. 견적서 항목 테이블

- **컬럼**: 품목명 | 설명 | 수량 | 단가 | 금액
- **각 행**: 동적 렌더링 (노션 데이터 기반)
- **계산**: 금액 = 수량 × 단가 (자동 계산)

##### 6. 합계 영역

- **소계**: 모든 항목의 합 (세금 제외)
- **세금 (VAT)**: 소계 × 10%
- **총액**: 소계 + 세금

##### 7. 추가 정보 영역

- **비고**: 추가 설명 (선택사항)
- **결제 조건**: 선택사항
- **유효기간 표시**: "이 견적서는 [유효기간]일 동안 유효합니다."

##### 8. 푸터 영역

- 회사 기본 정보 (선택사항)
- 인쇄 날짜 (인쇄 시에만 표시)

#### 사용자 행동 및 상호작용

| 액션            | 트리거                       | 결과                                                                  |
| --------------- | ---------------------------- | --------------------------------------------------------------------- |
| 페이지 로드     | URL 직접 접근 또는 링크 클릭 | 노션 API에서 데이터 페칭, 페이지 렌더링                               |
| [PDF 저장] 클릭 | 버튼 클릭                    | HTML to PDF 변환 후 다운로드 (파일명: 견적서*[번호]*[클라이언트].pdf) |
| [인쇄] 클릭     | 버튼 클릭                    | 브라우저 인쇄 대화상자 열기 (인쇄 CSS 자동 적용)                      |
| 페이지 스크롤   | 스크롤 이벤트                | 반응형 레이아웃 유지                                                  |
| 모바일 접근     | 모바일 기기                  | 모바일 최적화 레이아웃 표시                                           |

#### 주요 기능

1. **데이터 로딩**
   - SSG (Static Site Generation) 또는 ISR (Incremental Static Regeneration) 적용
   - 노션 API를 통한 실시간 데이터 페칭
   - 에러 처리: 데이터 없음, API 오류 시 적절한 메시지 표시

2. **자동 계산**
   - 각 항목: `금액 = 수량 × 단가`
   - 소계: 모든 항목의 금액 합
   - 세금: 소계 × 10% (VAT)
   - 총액: 소계 + 세금

3. **PDF 생성**
   - 라이브러리: `html2pdf` 또는 `puppeteer` (서버 렌더링)
   - 레이아웃 보존 (인쇄용 CSS)
   - 파일명 자동 생성

4. **반응형 디자인**
   - TailwindCSS로 브레이크포인트 관리
   - 모바일 (< 640px): 테이블 -> 카드 레이아웃 변환
   - 태블릿 (640px - 1024px): 2단 레이아웃
   - 데스크톱 (> 1024px): 기본 레이아웃

5. **인쇄 최적화**
   - `@media print` CSS 규칙 적용
   - 배경색 제거, 버튼 숨김
   - A4 용지 사이즈 자동 조정

6. **메타데이터**
   - OG 태그 (소셜 미디어 공유)
   - 페이지 타이틀: "견적서 - [견적번호] | 회사명"
   - 설명: "견적서: [견적번호] - [클라이언트명]"

#### 에러 처리

| 에러 시나리오               | 처리 방법                                          |
| --------------------------- | -------------------------------------------------- |
| 데이터를 찾을 수 없음 (404) | 친절한 메시지와 함께 홈페이지로 돌아가기 링크 제공 |

### 페이지 2: 관리자 대시보드 - 인증 (`/dashboard`)

**페이지 ID**: `P-02`

- 관리자만 대시보드에 접근할 수 있도록 패스워드 기반 인증 제공

1. **관리자**: `/dashboard` URL 직접 접근

#### 주요 구성 요소

##### 1. 레이아웃

- **중앙 정렬 카드**: 최대 너비 400px
- **배경**: 브랜드 컬러 또는 그래디언트
- **카드 배경**: 흰색 또는 밝은 배경

##### 2. 헤더 영역

- **필드**: 패스워드 입력 필드

- **[로그인] 버튼**: 폼 제출
  - Primary 버튼 스타일
  - Disabled 상태 (로딩 중)

##### 4. 에러 메시지 영역

- **잘못된 패스워드**: "패스워드가 올바르지 않습니다. 다시 시도해주세요."
- **필드 검증**: 빈 필드 입력 방지

##### 5. 추가 요소 (선택사항)

- **"패스워드를 잊으셨나요?"** 링크 (향후)
- **지원 문의** 링크

#### 사용자 행동 및 상호작용

| 액션          | 트리거              | 결과                                |
| ------------- | ------------------- | ----------------------------------- |

| Enter 키      | 입력 필드에서 Enter | 폼 제출 (패스워드 입력 후)          |

1. **패스워드 검증**
   - 환경 변수에서 올바른 패스워드 읽기 (`ADMIN_PASSWORD`)
   - 입력된 패스워드와 비교
   - 보안: 해시 기반 검증 (bcrypt 또는 유사)

2. **세션 관리**
   - 쿠키 기반 인증 (Server Action 활용)
   - 세션 유지 기간: 1시간 (기본값)
   - 세션 만료 시 자동 로그아웃

   - 필수 필드 검증
   - 최소 길이 검증 (예: 4자 이상)

4. **보안**
   - HTTPS 강제
   - XSS 방지 (Next.js 기본 보안)
   - CSRF 토큰 (Server Action 기본 지원)

5. **사용자 경험**
   - 로딩 상태 표시 (버튼 디스에이블, 스피너)
   - 명확한 에러 메시지
   - 엔터 키 지원 (폼 제출)

### 페이지 3: 관리자 대시보드 - 목록 및 관리 (`/dashboard` - 인증 후)

**페이지 ID**: `P-03`
**기능**: F-04, F-05
**권한**: 관리자 (인증 후)
**이전 페이지**: P-02 (인증 페이지)
**다음 페이지**: P-01 (견적서 미리보기)

#### 역할

- 관리자가 모든 견적서를 조회, 검색, 필터링할 수 있는 중앙 관리 페이지
- 각 견적서의 공개 링크를 손쉽게 복사하여 클라이언트에게 공유

#### 진입 경로

1. **관리자**: P-02 (인증 페이지)에서 인증 성공 후 자동 리다이렉트
2. **관리자**: 인증된 상태에서 `/dashboard` 직접 접근

#### 주요 구성 요소

##### 1. 헤더 영역

- **페이지 제목**: "견적서 관리"
- **로그아웃 버튼**: 우측 상단
- **새로고침 버튼** (선택사항): 데이터 동기화

##### 2. 검색 및 필터 영역

- **검색 바**: 견적번호, 클라이언트명으로 검색
  - placeholder: "견적번호 또는 클라이언트명 검색..."
  - 실시간 검색 (입력 후 즉시 필터링)
  - 지우기 버튼 (X)

- **정렬**: 발행일 기준
  - 드롭다운: "최신순", "오래된순"
  - 기본값: "최신순"

- **필터** (향후):
  - 상태: 모든 견적서, 유효, 만료됨

##### 3. 견적서 목록 테이블

- **컬럼**:
  1. **견적번호**: 예) INV-2026-001 (클릭 시 상세보기)
  2. **클라이언트명**: 예) ABC 주식회사
  3. **금액**: 통화 형식 (예: ₩1,234,567)
  4. **발행일**: YYYY-MM-DD
  5. **유효기간**: YYYY-MM-DD ~ YYYY-MM-DD
  6. **액션 버튼**:
     - [미리보기] 아이콘 (eye): P-01 (웹 뷰어)로 이동
     - [링크 복사] 아이콘 (link): 공개 링크를 클립보드에 복사
     - [추가 메뉴] 아이콘 (dots): 향후 추가 기능

- **행 당 항목 수**: 10-20개 (기본값: 15개)
- **페이지네이션**: 다음/이전 버튼 또는 페이지 번호

##### 4. 상태 표시

- **유효한 견적서**: 녹색 배지
- **만료된 견적서**: 회색 배지
- **곧 만료**: 주황색 배지 (유효기간 3일 이내)

##### 5. 빈 상태 (Empty State)

- 견적서가 없을 경우: "아직 견적서가 없습니다."
- 검색 결과가 없을 경우: "검색 결과가 없습니다. 다른 조건으로 시도해주세요."

##### 6. 푸터 영역

- **총 견적서 수**: 예) "총 15개의 견적서"
- **선택된 항목 수**: "선택됨: 0개" (향후 다중 선택)

#### 사용자 행동 및 상호작용

| 액션             | 트리거                     | 결과                                      |

   - 노션 API (F-06)를 통해 모든 견적서 조회
   - 캐싱: ISR 또는 온디맨드 재검증
   - 실시간 업데이트 (선택사항): 10초 간격 자동 새로고침

2. **검색 및 필터링**
   - 클라이언트 측 필터링 (작은 데이터셋)
   - 서버 측 필터링 (대규모 데이터셋, 향후)

3. **링크 복사**
   - 클립보드 API 사용
   - 토스트 메시지: "링크가 복사되었습니다!"
   - 3초 후 자동 사라짐

4. **세션 관리**
   - 인증 확인 (미들웨어 또는 서버 컴포넌트)
   - 로그아웃 시 세션 삭제

5. **반응형 디자인**
   - 모바일 (< 640px): 테이블 -> 카드 리스트로 변환
   - 태블릿 (640px - 1024px): 축약된 테이블 (일부 컬럼 숨김)
   - 데스크톱 (> 1024px): 전체 테이블

| 에러 시나리오    | 처리 방법                                                         |

## 부록: 기술 결정사항

### 1. 왜 노션 API인가?

- **장점**: 별도의 백엔드 DB 필요 없음, 마크다운 지원, 메디어 처리 용이
- **단점**: API 기한 (월 3회 호출 제한 가능성), 속도 (캐싱 필수)
- **해결**: ISR을 통한 캐싱으로 API 호출 최소화

### 2. 왜 Server Action인가?

- **장점**: 클라이언트-서버 경계 제거, 보안 (토큰 숨김), 간단한 폼 처리
- **단점**: 상태 관리 복잡함, 캐싱 어려움
- **해결**: 작은 규모 프로젝트이므로 충분함

### 3. 왜 패스워드 기반 인증인가?

- **목적**: MVP 범위에서 간단한 관리자 접근 제어
- **향후**: OAuth, JWT, 세션 기반 인증으로 확장

### 4. PDF 생성 방식

- **초기**: HTML to PDF (클라이언트 기반, `html2pdf.js`)
- **이유**: 배포 간단, 성능 우수, 별도 서버 리소스 불필요
- **향후**: 고품질 필요 시 `puppeteer` (서버) 전환
